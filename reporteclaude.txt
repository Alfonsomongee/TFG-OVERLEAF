C20. Antipatrón en los 45 slides de Modo Cine + bug de scrub hacia atrás
He muestreado Slide21.jsx, Slide12.jsx. Los 45 slides comparten exactamente este patrón:
jsxconst [stage, setStage] = useState(0);
useEffect(() => {
  if (slideProgress >= 0.2) setStage(1);
  if (slideProgress >= 0.5) setStage(2);
  if (slideProgress >= 0.8) setStage(3);
}, [slideProgress]);
Tres problemas:

stage es estado derivado, no estado de React. El valor depende 100% del prop slideProgress. No necesita useState ni useEffect. Cada cambio de slideProgress ya re-renderiza el componente; calcular stage en el render basta.
Bug funcional: el scrub hacia atrás no decrementa stage. Si el usuario está en slideProgress = 0.9 (stage = 3) y retrocede a slideProgress = 0.1, ninguna condición if (slideProgress >= …) se cumple, pero setStage no se llama con 0 — stage queda en 3. El bloque condicional {stage >= 3 && (...)} sigue renderizando contenido de la fase final aunque visualmente estés al principio. Es un fallo de coreografía que un revisor crítico verá en la defensa si reproduce el scrub.
El antipatrón se replica 45 veces. Cuando arregles el bug, hay que tocar 45 archivos.
