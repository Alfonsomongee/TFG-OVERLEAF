REGISTRO GLOBAL DE COMPONENTES MDX
================================================================================

Ubicación probable: src/theme/MDXComponents.js

Objetivo:
  Mapea elementos HTML estándar (h1, p, table, img, etc.) a componentes React custom
  Permite reutilizar lógica compleja en múltiples archivos MDX sin imports explícitos

Patrón:
  export default {
    h1: CustomH1,
    h2: CustomH2,
    p: CustomP,
    table: CustomTable,
    img: CustomImg,
    a: CustomLink,
    ...otrosElementos
  }

PROPIEDADES DOCUSAURUS EN MDX
================================================================================

Metadata de front-matter disponible en MDX:

```mdx
---
slug: /ruta-custom
sidebar_position: 1
hide_title: true
title: "Título de página"
---
```

Variables inyectadas automáticamente en MDX:
  - metadata (objeto con frontMatter)
  - toc (table of contents generado)
  - isFrontPage (boolean si es la página de inicio)

Uso en MDX:
  {frontMatter.title}
  {metadata.custom_prop}

================================================================================
PLUGINS REMARK Y REHYPE
================================================================================

Configuración en docusaurus.config.js:

remarkPlugins:
  1. remark-math (strict: false)
     → Procesa delimitadores $...$ y $$...$$
     → Genera tokens para rehype-katex

  2. remark-auto-glossary-links (custom)
     → Detecta términos del glosario
     → Envuelve con tooltip/link automático
     → Probablemente usa glosario en docs/glosario.mdx

rehypePlugins:
  1. rehype-katex (strict: false)
     → Renderiza matemáticas con KaTeX
     → CDN: cdn.jsdelivr.net/npm/katex@0.15.0

IMPLICACIONES:
  - MDX files pueden usar LaTeX: $E=mc^2$
  - Términos automáticamente linkeados al glosario
  - Matemáticas renderizadas server-side (no JS adicional en cliente)

================================================================================
INTEGRACIÓN CON DOCUSAURUS
================================================================================

MDXComponents.js se carga en:
  1. src/theme/MDXComponents.js (donde se define el mapa)
  2. Root.js o Layout/index.js (donde se proporciona a <MDXProvider>)

Propósito:
  <MDXProvider components={MDXComponents}>
    {children}
  </MDXProvider>

Esto hace que todos los elementos de MDX usen los componentes custom.

================================================================================
PROBLEMAS POTENCIALES
================================================================================

1. **Conflicto de nombres**
   - Si MDXComponents.js registra componentes que también existen como imports
   - Ejemplo: Si hay un <Table /> custom global pero también se importa otro

2. **Props no pasadas**
   - Si MDXComponents no pasa todas las props (className, id, etc.)
   - Puede romper styling o accesibilidad

3. **Rendimiento**
   - Componentes custom complejos en cada elemento puede ralentizar
   - Alternativa: Usar clases CSS en lugar de componentes React

4. **Mantenimiento**
   - Si Docusaurus cambia estructura de MDXComponents
   - Requiere actualización manual
