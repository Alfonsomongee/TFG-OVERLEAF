PUNTOS CRÍTICOS PARA OPUS 4.7
================================================================================

Si Opus 4.7 necesita hacer cambios profundos, estos son puntos críticos:

1. ROUTING Y SLUGS:
   ⚠ routeBasePath: '/' en docusaurus.config.js
   → Docs se sirven en raíz, no en /docs/
   → Cambiar esto requiere actualizar TODAS las URLs

2. SWIZZLED COMPONENTS:
   ⚠ 9 componentes personalizados en src/theme/
   → Cualquier upgrade de Docusaurus 2.4 → 3.0 requiere actualización manual
   → Probablemente romperá si se cambian componentes base

3. CUSTOM CSS (3773 líneas):
   ⚠ Single custom.css file sin modularización
   → Cambios de tema requieren editar variables CSS centralizadas
   → No hay Tailwind o PostCSS (puro vanilla CSS)

4. API INTEGRACIÓN:
   ⚠ /api/chat.js (serverless function) requiere clave de Anthropic
   ⚠ /api/esios-analysis.js requiere configuración de providers LLM
   → Sin keys configuradas, funcionalidad falla silenciosamente

5. DATOS EN TIEMPO REAL:
   ⚠ Componentes en datos-tiempo-real/ hacen fetch a ESIOS API
   → Si API cae, componentes muestran skeleton indefinidamente
   → No hay fallback a datos estáticos

6. GLOSARIO AUTOMÁTICO:
   ⚠ remark-auto-glossary-links (custom plugin)
   → Si plugin falla, tooltips no aparecen
   → Documentación técnica se vuelve menos accesible

PREGUNTAS FRECUENTES PARA OPUS 4.7
================================================================================

P1: ¿Cuál es el principal propósito del sitio?
R: TFG interactivo que documenta el apagón ibérico del 28-A con análisis técnico
  profundo, gráficos dinámicos, simuladores interactivos y datos en tiempo real.

P2: ¿Cuánta documentación hay?
R: 13+ capítulos (01-introduccion a 08.5-actualizacion-2026), 8 anexos,
  12 páginas de datos en tiempo real. Total ~100+ páginas compiladas.

P3: ¿Cuál es el audience?
R: Estudiantes de ingeniería, profesionales del sector, investigadores, público
  general. Multiidioma (es/en/de/zh-Hans).

P4: ¿Cómo funciona el análisis LLM?
R: Cada componente de datos-tiempo-real usa useEsiosAnalysis hook que:
  1. Fetch data de ESIOS API
  2. POST a /api/esios-analysis con data + metric name
  3. Claude API genera 2-sentence análisis
  4. Cache 5 minutos, revalidate en timeout

P5: ¿Cuál es el principal riesgo?
R: Dependencias envejecidas (React 17, Docusaurus 2.4) y componentes swizzled
  que romperán en upgrade. Requiere plan de modernización.

P6: ¿Cuál es el workflow típico de edición?
R: 1. Editar .mdx en docs/ 2. npm run build 3. Deploy a Vercel
  Prebuild genera índice de búsqueda (scripts/build-index.js)

P7: ¿Cómo se agrega nuevo contenido?
R: Crear archivo .mdx en docs/, añadir a sidebars.js con sidebar_position,
  incluir frontMatter (title, slug, etc.). Si usa componentes custom, importar
  en la cabeza del archivo.

CONCLUSIÓN
================================================================================

El proyecto tfg-antigravity-docs es un sitio Docusaurus bien-estructurado,
visualmente cohesivo, y tecnológicamente ambicioso. Combina:

  ✓ Documentación técnica rigurosa
  ✓ Visualizaciones interactivas de datos
  ✓ Integración de IA (Claude API)
  ✓ Búsqueda offline multiidioma
  ✓ Diseño responsivo y accesible

Sus principales desafíos son:

  ⚠ Dependencias envejecidas (React 17, Docusaurus 2.4)
  ⚠ Componentes swizzled complejos
  ⚠ CSS monolítico (3773 líneas)
  ⚠ Dependencia crítica de APIs externas

Un plan claro de modernización permitiría que el proyecto escale y se mantenga
indefinidamente.
