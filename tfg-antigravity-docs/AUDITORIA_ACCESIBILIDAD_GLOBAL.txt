================================================================================
ACCESIBILIDAD VISUAL
================================================================================

1. CONTRASTE DE COLOR (WCAG 2.1 Level AA):
   Mínimo: 4.5:1 para texto normal
   Mínimo: 3:1 para texto grande (18pt+)

   ANÁLISIS PROBABLE:

   Dark mode:
   - Fondo #0a1128, texto #ffffff → muy alto contraste ✓
   - Fondo #0a1128, texto #e8e8e8 → ~16:1 ✓

   Light mode:
   - Fondo #F4F1EA, texto #2B2B2B → ~10:1 ✓

   Elementos interactivos:
   - Cian (#00D9FF) sobre #0a1128 → revisar
   - Burdeos (#8B2635) sobre #F4F1EA → revisar

   ⚠ RIESGO: Enlaces azules pueden tener bajo contraste en light mode

2. TAMAÑO DE TEXTO:
   - Mínimo legal: 12px (algunos países)
   - Recomendado: 14px+
   - Docusaurus por defecto: 16px (--fs-body clamp)
   ✓ Probable cumplimiento

3. ESCALABILIDAD:
   - Usuario debe poder zoomar hasta 200% sin que el contenido se corte
   - Docusaurus soporta zoom nativo del navegador
   - Componentes custom: ¿respetan max-width y overflow?
   ⚠ Requiere testing con zoom

4. INDICADORES VISUALES:
   - Focus visible (cuando navegas con Tab)
   - Docusaurus probablemente tiene default focus outline
   - Componentes custom: ¿tienen focus visible?
   ⚠ Requiere auditoría de cada componente

================================================================================
ACCESIBILIDAD SEMÁNTICA (HTML)
================================================================================

1. HEADINGS:
   Recomendación: <h1> una por página, luego <h2>, <h3>, no saltar niveles
   ⚠ Requiere auditoría de cada MDX

2. LANDMARKS:
   - <header> para navbar
   - <nav> para sidebar
   - <main> para contenido
   - <footer> para pie de página
   ✓ Probable: Docusaurus genera automáticamente

3. LISTAS:
   - <ul>/<ol> para listas, no divs
   ✓ Probable: MDX genera correctamente

4. TABLAS:
   - <thead>, <tbody>, <th> con scope
   - ForensicTable: ¿genera semántica correcta?
   ⚠ Requiere inspección

5. FORMULARIOS (si existen):
   - <label> vinculado a <input> (for="id")
   - Error messages vinculados con aria-describedby
   ⚠ Chat input probablemente necesita auditoría

================================================================================
ARIA (Accessible Rich Internet Applications)
================================================================================

1. LANDMARK ROLES:
   - role="navigation" en sidebar
   - role="main" en contenido
   - role="complementary" en TOC
   ⚠ Probable Docusaurus lo añade, verificar

2. LIVE REGIONS:
   - aria-live="polite" en chat messages
   - aria-live="assertive" en alerts
   ⚠ Requiere testing con screen reader

3. LABELS Y DESCRIPTIONS:
   - aria-label="Cerrar modal" en botones X
   - aria-describedby en elementos complejos
   ⚠ Probable deficiencia en componentes custom

4. EXPANDED STATE:
   - aria-expanded="true|false" en collapses
   - StickyCollapse: ¿tiene aria-expanded?
   ⚠ Probable deficiencia

5. DISABLED STATE:
   - aria-disabled en botones deshabilitados
   - disabled attribute en inputs

2. Navegación:

3. Formularios:

   - ¿Anuncia cambios en chat?

⚠ Probable: Docusaurus base es accesible, pero componentes custom pueden no serlo

Herramientas automatizadas:

⚠ RECOMENDACIÓN: Ejecutar axe + Lighthouse en cada página

================================================================================
PROBLEMAS IDENTIFICABLES SIN TESTING
================================================================================

Probables deficiencias:

1. **Componentes custom sin aria labels**
   - Chat widget sin role="dialog"
   - Botón flotante sin aria-label
   - Collapses sin aria-expanded

2. **Color como único indicador**
   - ¿Hay elementos solo diferenciados por color?
   - Deben tener patrón, ícono o texto adicional

3. **Imágenes sin alt text**
   - Gráficos de datos: ¿tienen alt text descriptivo?
   - Logos: ¿tienen alt="" (decorativo) o alt="..."?

4. **Links sin contexto**
   - "Click aquí" → texto no descriptivo
   - Mejor: "Lee más sobre la cascada"

5. **Tablas sin headers**
   - ForensicTable: ¿usa <thead>?
   - Datos28A.json: ¿cómo se renderizan?

6. **Contraste en estados**
   - Focus state: ¿visible?
   - Hover state: ¿tiene suficiente contraste?
   - Disabled state: ¿se ve diferente?
