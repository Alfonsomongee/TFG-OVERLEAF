F) ACTUAL GENERATION OUTPUT PER GENERATION UNIT (TR 16.1.A)

Mientras las previsiones indicaban una generación solar superior a 12 GW y eólica de 3,5 GW a mediodía, los registros de las unidades muestran una práctica totalidad de la fotovoltaica en cero y la eólica reducida a un 5% de lo esperado. Esta caída no se debió a falta de recurso primario, sino a la desconexión masiva por sobretensión en redes colectoras de 220 kV, invisible para el operador. Por el contrario, la generación hidroeléctrica y nuclear se mantuvieron estables, demostrando su papel crítico como ‘andamiaje electromagnético’ durante la cascada y la posterior reposición.” 

Relevancia: Alta (granularidad). Mientras que TR 16.1.B&C muestra agregados por tecnología, este desglose por unidad individual permite identificar si centrales específicas sufrieron problemas (desconexiones no programadas, reducciones de potencia, etc.) en las horas previas al colapso. Anomalías en generadores específicos pueden ser causa o consecuencia del apagón.

Todos los generadores solares aparecen con potencia cero (0.00 MW). Esto es consistente con un instante posterior al colapso (Fase 3 o Fase 4) o con un momento de baja irradiación, pero dado el contexto del apagón (mediodía del 28 de abril), es más probable que refleje la desconexión masiva por sobretensión durante la cascada o el cero eléctrico posterior.

La generación eólica muestra valores reducidos (entre 4.4 MW y 75.2 MW), también muy por debajo de lo esperable (dado que la previsión era alta). Esto sugiere que muchas plantas eólicas también se desconectaron por sobretensión o por pérdida de sincronismo.

La generación hidroeléctrica y de bombeo presenta valores significativos (por ejemplo, Aldea I con ~100 MW por unidad, Muela con ~150 MW por unidad), indicando que estos activos permanecieron conectados y fueron clave para la reposición Bottom-Up (Fase 4). Algunas unidades de bombeo están a cero (modo motor o paradas).

La generación nuclear muestra una situación mixta: Almaraz 1 y Cofrentes a cero (posiblemente disparadas), mientras que Almaraz 2, Ascó 1, Ascó 2 y Vandellós están operando (643 MW a 1044 MW). Esto refleja que no todas las nucleares colapsaron; algunas resistieron el transitorio o fueron reconectadas durante la reposición.

Los ciclos combinados de gas presentan una mezcla de unidades a cero y otras con potencias entre 80 MW y 220 MW. Muchas de las que están a cero podrían haber sido las que estaban apagadas por orden de mérito antes del colapso (las que aportaban inercia pero fueron desplazadas por renovables). Las que están operativas corresponden probablemente a las que se utilizaron durante la «Operación Reforzada» para proveer firmeza.

Los valores N/A y n/e se han excluido; las unidades con esos códigos no se incluyen en el JSON para mantener la limpieza de los datos. Si consideras que deben aparecer igualmente con power_mw: null, dímelo y los añado.

Código:

jsx
import React from 'react';
import { BarChart, Bar, XAxis, YAxis, Tooltip, ResponsiveContainer, Cell, ReferenceLine } from 'recharts';

// Calcular variación semanal
const weeklyDelta = data.map((item, idx, arr) => {
  if (idx === 0) return { ...item, delta: 0, trend: 'flat' };
  const delta = item.mwh - arr[idx - 1].mwh;
  const trend = delta > 0 ? 'up' : delta < 0 ? 'down' : 'flat';
  return { ...item, delta, trend };
});

const getBarColor = (delta) => {
  if (delta > 0) return '#10b981';  // verde → llenado
  if (delta < 0) return '#ef4444';  // rojo → vaciado
  return '#94a3b8';                  // gris
};

export default function HydroDeltaChart() {
  return (
    <ResponsiveContainer width="100%" height={400}>
      <BarChart data={weeklyDelta} margin={{ top: 20, right: 30, left: 20, bottom: 20 }}>
        <XAxis dataKey="week" tickFormatter={(w) => `S${w}`} />
        <YAxis tickFormatter={(v) => `${(v / 1000).toFixed(0)} GWh`} />
        <Tooltip
          formatter={(value) => [`${(value / 1000).toFixed(1)} GWh`, 'Variación']}
          labelFormatter={(w) => `Semana ${w}`}
        />
        <Bar dataKey="delta">
          {weeklyDelta.map((entry, idx) => (
            <Cell key={`cell-${idx}`} fill={getBarColor(entry.delta)} />
          ))}
        </Bar>
        <ReferenceLine y={0} stroke="#64748b" strokeWidth={2} />
      </BarChart>
    </ResponsiveContainer>
  );
}

Código (con recharts no es nativo, pero puedes usar plotly.js o un heatmap grid manual). Te propongo una versión simple con celdas coloreadas:

jsx
import React from 'react';
import styles from './HydroHeatmap.module.css';

const weeksPerRow = 13; // 4 filas de 13 semanas (52)

const getColorByValue = (mwh) => {
  const max = 15500000; // ~15.5 TWh
  const intensity = mwh / max;
  if (intensity < 0.3) return '#2c3e50';
  if (intensity < 0.5) return '#1abc9c';
  if (intensity < 0.7) return '#27ae60';
  if (intensity < 0.9) return '#f1c40f';
  return '#e67e22';
};

export default function HydroHeatmap() {
  const weeks = data.map(d => ({ week: d.week, mwh: d.mwh }));
  
  return (
    <div className={styles.heatmapGrid} style={{ display: 'grid', gridTemplateColumns: `repeat(${weeksPerRow}, 1fr)` }}>
      {weeks.map((week, idx) => (
        <div
          key={idx}
          style={{
            backgroundColor: getColorByValue(week.mwh),
            padding: '8px 4px',
            textAlign: 'center',
            fontSize: '10px',
            color: '#fff',
            fontWeight: 'bold',
            border: '1px solid rgba(255,255,255,0.1)'
          }}
          title={`Semana ${week.week}: ${(week.mwh / 1e6).toFixed(1)} TWh`}
        >
          S{week.week}
        </div>
      ))}
    </div>
  );
}

Gráfico 1: Evolución del saldo neto comercial (España con Francia + Portugal)
jsx
import React from 'react';
import {
  LineChart,
  Line,
  XAxis,
  YAxis,
  CartesianGrid,
  Tooltip,
  ResponsiveContainer,
  ReferenceLine,
  Label
} from 'recharts';

// Cargar los datos (puedes importar el JSON directamente)
import data from './scheduled_commercial_exchanges_28_29_april_2025.json';

// Preparar datos para el gráfico: extraer timestamp y saldo neto total
const chartData = data.data.map(entry => ({
  time: entry.mtu_start.split(' ')[1], // hora: "00:00"
  datetime: entry.datetime,
  netBalance: entry.net_export_import_total === 'Export'
    ? entry.net_value_total
    : -entry.net_value_total  // negativo para importaciones
}));

// Encontrar el punto del apagón (12:30 - 12:45)
const blackoutPoint = chartData.find(d => d.time === '12:30');

export default function NetCommercialBalanceChart() {
  return (
    <ResponsiveContainer width="100%" height={400}>
      <LineChart data={chartData} margin={{ top: 20, right: 30, left: 20, bottom: 20 }}>
        <CartesianGrid strokeDasharray="3 3" opacity={0.3} />
        <XAxis
          dataKey="time"
          label={{ value: 'Hora (UTC)', position: 'insideBottom', offset: -5 }}
          interval={8} // mostrar cada 2 horas aprox
        />
        <YAxis
          label={{ value: 'Saldo neto (MW)', angle: -90, position: 'insideLeft' }}
          tickFormatter={(v) => `${v} MW`}
        />
        <Tooltip
          formatter={(value) => [`${value > 0 ? 'Exportación' : 'Importación'} ${Math.abs(value)} MW`, 'Saldo neto']}
          labelFormatter={(label, payload) => payload[0]?.payload.datetime || label}
        />
        <Line
          type="monotone"
          dataKey="netBalance"
          stroke="#10b981"
          strokeWidth={2}
          dot={{ r: 2 }}
          activeDot={{ r: 6 }}
          name="Saldo neto"
        />
        {/* Línea vertical del apagón */}
        {blackoutPoint && (
          <ReferenceLine
            x={blackoutPoint.time}
            stroke="#ef4444"
            strokeWidth={2}
            strokeDasharray="6 6"
            label={<Label value="⚡ Apagón" position="top" fill="#ef4444" fontSize={12} />}
          />
        )}
      </LineChart>
    </ResponsiveContainer>
  );
}
Gráfico 2: Flujos desglosados por frontera (barras apiladas)
jsx
import React from 'react';
import { BarChart, Bar, XAxis, YAxis, Tooltip, ResponsiveContainer, Legend, ReferenceLine } from 'recharts';

// Preparar datos con flujos netos por frontera
const borderData = data.data.map(entry => ({
  time: entry.mtu_start.split(' ')[1],
  datetime: entry.datetime,
  es_to_fr_net: entry.es_to_fr_total - entry.fr_to_es_total,
  es_to_pt_net: entry.es_to_pt_total - entry.pt_to_es_total
}));

export default function BorderFlowsChart() {
  return (
    <ResponsiveContainer width="100%" height={400}>
      <BarChart data={borderData} margin={{ top: 20, right: 30, left: 20, bottom: 20 }}>
        <CartesianGrid strokeDasharray="3 3" opacity={0.3} />
        <XAxis dataKey="time" interval={8} />
        <YAxis label={{ value: 'Flujo neto (MW)', angle: -90, position: 'insideLeft' }} />
        <Tooltip
          formatter={(value, name) => [
            `${value > 0 ? 'Exportación' : 'Importación'} ${Math.abs(value)} MW`,
            name === 'es_to_fr_net' ? 'España → Francia' : 'España → Portugal'
          ]}
          labelFormatter={(label, payload) => payload[0]?.payload.datetime || label}
        />

M) Fall-backs
⚙️ Fallbacks en el mercado eléctrico europeo
Aunque son un concepto muy amplio, los fallbacks juegan un papel particularmente visible en el mercado eléctrico, asegurando su funcionamiento cuando los sistemas estándar no pueden operar:

Finalidad clave: Su objetivo principal es mantener la estabilidad y seguridad del suministro eléctrico cuando se produce una disrupción en los procesos del mercado, como el acoplamiento diario (Day-Ahead Coupling).

Marco legal: Están regulados en base al Artículo 44 del Reglamento (UE) 2015/1222 de la Comisión (conocido como Reglamento CACM), que establece las directrices para el acoplamiento del mercado diario y los procedimientos de contingencia asociados.

Manual de referencia: La guía de referencia en este ámbito es el "SDAC Fallback Manual" (Manual de Contingencia del Acoplamiento Diario). Este manual, elaborado por ENTSO-E y los Operadores del Mercado Eléctrico (NEMOs), proporciona directrices claras para responder eficazmente a una desconexión parcial o total del acoplamiento.

🧐 Importancia de los fallbacks en el Apagón de 2025
En el devastador apagón que afectó a España y Portugal el 28 de abril de 2025, los fallbacks demostraron ser un arma de doble filo, donde la falta de unos procedimientos automáticos y robustos contribuyó al caos, mientras que otros fueron vitales para la recuperación:

La ausencia de automatización agravó el colapso: Según el informe final de los expertos de ENTSO-E, la desconexión del sistema no se debió a un fallo único, sino a una combinación de factores donde la falta de procedimientos automáticos jugó un papel crítico. Equipos clave para controlar la potencia reactiva (como los reactores en derivación) requerían activación manual por parte de los operadores, un proceso demasiado lento para una crisis que se desencadenó en menos de 90 segundos.

Procedimientos de restauración exitosos: Una vez producido el apagón, los procedimientos de contingencia y restauración ("fallback strategies") del sistema demostraron su eficacia. Gracias a estos protocolos y al compromiso de todos los agentes, el suministro se restableció por completo en Portugal tras 12 horas y en España tras 16.

Por tanto, el fallback no fue una causa del apagón, sino la función ausente que contribuyó a que este fuera inevitable. Su importancia radica en que, de haber sido más robustos y automatizados, podrían haber mitigado o incluso evitado la magnitud de una crisis que dejó a 50 millones de personas sin electricidad. Su versatilidad, en cambio, fue clave para una exitosa recuperación posterior.

N) Installed Capacity per Production Type


La capacidad instalada del sistema eléctrico peninsular (≈122 GW) muestra un equilibrio aparente entre fuentes renovables basadas en inversores (IBR) – fundamentalmente solar (29 GW) y eólica (31 GW) – y generación síncrona convencional (gas, nuclear, hidráulica, carbón, etc.), que suman aproximadamente 61 GW. A primera vista, el parque síncrono parece suficiente para garantizar la estabilidad dinámica.

Sin embargo, el apagón del 28 de abril de 2025 demostró que la capacidad instalada es un pésimo indicador de resiliencia. Ese día, por orden de mérito económico, la práctica totalidad de los ciclos combinados de gas (∼30 GW de capacidad) estaban apagados, y la generación nuclear operaba al mínimo (solo 3,4 GW de los 7 GW instalados). La generación real estaba dominada por IBR (82% del mix instantáneo), con la solar fotovoltaica aportando más de 18 GW.

Cuando la cascada de sobretensiones desconectó masivamente los inversores solares y eólicos, el sistema perdió instantáneamente su principal fuente de energía activa y, más críticamente, su capacidad de absorción de potencia reactiva inductiva. La generación síncrona remanente – hidroeléctrica (∼3,5 GW) y nuclear (∼3,4 GW) – no pudo compensar el déficit de reactiva (estimado en >0,7 GVAr sólo en la zona sur).

La lección estructural es clara: la capacidad instalada síncrona no sirve si está desconectada por razones de mercado. El colapso no fue un problema de recursos energéticos totales, sino de disponibilidad operativa de máquinas rotatorias en el momento crítico. La gráfica de capacidad instalada debe leerse junto con la de generación real (que aquel día mostraba solar a cero y eólica reducida al 5% de lo esperado) para comprender la verdadera vulnerabilidad del sistema.

🔍 ¿Qué revelan estos datos? (Análisis forense)
1. El valle de demanda – condición necesaria para el efecto Ferranti
En España, la demanda real antes del colapso (valores hasta las 10:00) se situaba entre 25.000 y 27.000 MW, muy por debajo de la punta histórica (>45.000 MW). Esta demanda inusualmente baja (≈56 % de la punta) es una de las condiciones que permitió que las líneas de 400 kV subcargadas se comportaran como grandes bancos de condensadores por efecto Ferranti, inyectando reactiva capacitiva que saturó los márgenes de absorción del sistema.

2. La “falsa normalidad” de la previsión
Las previsiones day-ahead para España el 28 de abril eran notablemente precisas para las horas previas al colapso (diferencia <2 %). Esto indica que el operador conocía con antelación el perfil de baja demanda que se iba a producir. A pesar de ello, no se adoptaron medidas preventivas como mantener más grupos síncronos en servicio o activar compensadores de reactiva adicionales. La previsibilidad del escenario convierte el apagón en un fallo de gestión del riesgo, no en un “cisne negro”.

3. El colapso de la demanda registrada (Portugal como termómetro)
A partir de las 10:00-11:00, los datos de demanda real para España desaparecen (null). Esta ausencia de datos es, paradójicamente, la prueba más evidente del colapso: el sistema de telemedida y SCADA dejó de recibir valores fiables porque la red de transporte se había desenergizado. En Portugal, en cambio, sí se registran valores reales durante toda la tarde del 28 de abril, aunque extremadamente reducidos:

La demanda real de Portugal actúa como un “termómetro” de la reposición: su lenta recuperación durante la tarde del 28 de abril refleja la dificultad de re-energizar una red sin suficiente masa síncrona.

4. La recuperación completa llega al final del 29 de abril
España no vuelve a tener valores de demanda real hasta el tramo 22:00-23:00 del 29 de abril, donde se registran 22.801 MW (frente a una previsión de 21.924,5 MW). Esto indica que la reposición completa del sistema español requirió casi 19 horas (desde las 12:33 del 28 hasta las 22:00-23:00 del 29). Portugal, en cambio, se recuperó antes (hacia las 20:00-21:00 del 28 de abril ya tenía 2.642 MW, pero no alcanza valores normales hasta la madrugada del 29).

5. La paradoja de la “demanda desaparecida”
El hecho de que España no tenga datos reales desde las 10:00-11:00 hasta las 22:00-23:00 del 29 de abril es, en sí mismo, un dato forense de enorme valor. La ausencia de medición certifica el cero de tensión. Cuando un sistema de telemedida deja de reportar valores, no es un error técnico menor: es la constatación de que la red de transporte ha perdido la tensión necesaria para alimentar los propios equipos de medición.

O) Energy Prices

“Los precios day-ahead del mercado mayorista ibérico (OMIE) el 28 de abril de 2025 muestran una caída a valores negativos a partir de las 09:00, alcanzando –3,00 €/MWh en la hora del colapso (12:00-13:00). Esta evolución refleja un excedente estructural de generación renovable, principalmente solar, que obligó a desconectar por orden de mérito a los ciclos combinados de gas, principales proveedores de inercia y potencia de cortocircuito. Al retirar estas máquinas síncronas, el sistema perdió su capacidad de absorber potencia reactiva inductiva, creando las condiciones ideales para que el efecto Ferranti de las líneas de 400 kV subcargadas inyectara reactiva capacitiva en una red ya saturada.*

*Es importante señalar que los precios day-ahead se determinan 24 horas antes, basándose en previsiones. Por lo tanto, el precio negativo de la hora 12:00-13:00 no es una consecuencia del apagón, sino una señal económica previa que advertía del riesgo de operar con baja inercia. La gestión de la crisis no supo interpretar esa señal.*

*Al día siguiente, 29 de abril, el mercado recuperó la normalidad, aunque persistieron precios reducidos o negativos durante las horas centrales. Sin embargo, el repunte vespertino (35 €/MWh en España a las 22:00) refleja el mayor uso de gas para asegurar la estabilidad tras el colapso, un sobrecoste que se trasladó a los consumidores.”

Gráfica recomendada: gráfico de barras o de líneas con área coloreada según situación (déficit/superávit)
Eje X: tiempo (cada 15 minutos desde el 28 de abril 00:00 hasta el 29 de abril 23:45 UTC).

Eje Y: imbalance (MWh). Escalar hasta 1800 MWh para cubrir el pico.

Colores: rojo para déficit, verde/azul para superávit.

Línea vertical en el momento del apagón (10:30 UTC del 28 de abril, aprox. 12:30 CEST).

Etiquetas con los valores más relevantes (pico de déficit, momento de cambio a superávit).

Código básico (React + Recharts)
jsx
import React from 'react';
import { ComposedChart, Area, XAxis, YAxis, CartesianGrid, Tooltip, ReferenceLine, ResponsiveContainer } from 'recharts';
import data from './imbalance_spain_28_29_april_2025.json';

// Combinar los datos de ambos días en un único array
const chartData = [
  ...data.data['2025-04-28'].map(d => ({ ...d, date: d.datetime.slice(0,10), time: d.datetime.slice(11,16) })),
  ...data.data['2025-04-29'].map(d => ({ ...d, date: d.datetime.slice(0,10), time: d.datetime.slice(11,16) }))
];

// Crear una columna con el valor firmado (positivo = déficit, negativo = superávit)
// Para mantener la claridad, usaremos valores positivos pero con color condicional.
// En Recharts podemos usar dos áreas: una para déficit y otra para superávit.

const deficitData = chartData.map(d => d.situation === 'Deficit' ? { ...d, imbalance_mwh: d.imbalance_mwh } : { ...d, imbalance_mwh: 0 });
const surplusData = chartData.map(d => d.situation === 'Surplus' ? { ...d, imbalance_mwh: d.imbalance_mwh } : { ...d, imbalance_mwh: 0 });

export default function ImbalanceChart() {
  return (
    <ResponsiveContainer width="100%" height={450}>
      <ComposedChart data={chartData} margin={{ top: 20, right: 30, left: 20, bottom: 20 }}>
        <CartesianGrid strokeDasharray="3 3" />
        <XAxis dataKey="datetime" tickFormatter={(t) => t.slice(11,16)} interval={12} />
        <YAxis label={{ value: 'Imbalance (MWh)', angle: -90, position: 'insideLeft' }} domain={[0, 1800]} />
        <Tooltip
          formatter={(value, name) => [`${value} MWh`, name === 'deficit' ? 'Déficit' : 'Superávit']}
          labelFormatter={(label) => label.replace('T', ' ')}
        />
        <ReferenceLine x="2025-04-28T10:30:00Z" stroke="#ef4444" strokeWidth={2} strokeDasharray="6 6" label={{ value: 'Apagón', position: 'top', fill: '#ef4444' }} />
        <Area type="monotone" dataKey="imbalance_mwh" data={deficitData} fill="#ef4444" stroke="#dc2626" name="Déficit" />
        <Area type="monotone" dataKey="imbalance_mwh" data={surplusData} fill="#10b981" stroke="#059669" name="Superávit" />
      </ComposedChart>
    </ResponsiveContainer>
  );
}

r) Actual Capacities and Outlook on FRR and RR 2025

¿Tenía España suficiente reserva FRR el día del apagón?
Estos datos muestran la capacidad de Reserva de Restauración de Frecuencia (FRR) –tanto para subir como bajar generación– que el operador español (REE) tenía disponible durante 2025. El segundo trimestre (Q2) incluye el fatídico 28 de abril.

Lo que se ve en la gráfica:

La capacidad prevista (outlook) era de 1600 MW tanto en subida como en bajada.

La capacidad real disponible (actual capacity) fue, de media, de ~1190 MW en Q2, con un mínimo de 889 MW (subida) y un máximo puntual de 1624 MW (bajada).

Aunque la media se mantenía por encima de los 1100 MW, existían momentos puntuales con apenas 889 MW de reserva útil.

Relación con el apagón:
El desencadenante fue la súbita pérdida de importación desde Francia (≈1200 MW). Para compensar ese déficit, la FRR automática debería haber saltado en segundos. Sin embargo, el informe de ENTSO-E señala que parte de la reserva requería activación manual y que los sistemas automáticos no respondieron con la suficiente rapidez. Disponer de una reserva contratada no basta si su activación no es instantánea y fiable.

Estos números confirman que, en papel, la capacidad de FRR era suficiente para cubrir el desequilibrio inicial, pero la lentitud de los procedimientos y la falta de automatización impidieron que se usara a tiempo, contribuyendo al colapso total del sistema.
